日期：2026-10-30。对应 [第五轮架构审查](../reviews/2026-10-29-fifth-architecture-review.md)。基线为 Git `0a4342e` 及其后的本地 UI 改动；本记录描述当前工作区，未提交、推送或部署生产。

## 工程边界

Python FastAPI 是唯一业务后端；Next.js 保留页面与浏览器 Cookie BFF，两套微信原生工程分别服务代理和老板。继续采用模块化单体，数据库承担资金约束。

旧 `src/` Node 后端、旧根测试和 Prisma 工具链已退出日常工程。迁移 SQL 原样冻结在 `python_backend/migrations/sql/`，Alembic 成为唯一迁移入口；旧实现可从 Git 基线恢复。旧分润结果已转为 20 组金额 fixture，原 API 契约保存为完整测试快照。没有通过修改语言统计伪装 Python 迁移。

路由保持兼容；原有请求和响应结构由契约测试检查。资金路由按订单、账户、提现、恢复、健康拆分，HTTP 层调用服务。没有为了目录形式一次性移动全部稳定模块。

## 已关闭的主要问题

- **F1 退款乱序**：有效退款在持久化接收时建立订单保护，与钱包提现和付款认领串行化；后到支付在同一事务内完成退款归并，不释放中间佣金。重复支付不能复活已退款订单，已发生付款仍记录真实结果。
- **F2 会话竞态**：鉴权传递不可变身份与原 token_version；创建票据在用户锁内校验。旧请求不能继承退出后的新版本；过期的退出请求也不能撤销后来新建的会话。
- **F3 对账缺口**：分润日志和实际钱包变动双向匹配，检查漏记、多记、错人和错金额；历史 opening 截止单独处理。差异持久化并可互斥认领，只有后续对账通过才自动关闭。
- **F4 页面状态**：概览、推广、钱包等资源独立管理；只有身份错误触发登录门禁。刷新保留页码和展开明细，失败范围与旧数据时间明确，资金页响应全局刷新。
- **F5 原生乱序**：提现分页增加请求序号及隐藏/卸载保护，旧响应不覆盖新页面；冷启动先完成身份恢复。
- **F6 结果未知**：Web 和原生保存固定申请编号、金额、账户，按已验证用户隔离；查询原结果或原样重试。账户切换和迟到响应不会复用或清除另一用户的申请。
- **F7 换卡流程**：待核验/有效/退役/驳回账户版本，审核通过切换未来申请；历史提现仍引用旧账户，账户身份不可原地改写。支持驳回原因与重新申请。
- **F8 请求体限制**：BFF 按流式 UTF-8 字节计数，上限 8192 bytes，越限取消读取；Content-Length 只用于提前拒绝。

## 架构、交付与 UI

补齐 ORM 索引与 CHECK 描述；数据库结构清单覆盖列、类型、默认值、NULL、约束、索引、enum、函数和触发器。旧库接管必须核对结构和已有迁移历史，拒绝漂移；升级事务与回滚均有真实 PostgreSQL 测试。

worker 的恢复与全量对账独立调度，记录成功周期和脱敏错误位置；资金中心显示任务健康、重试耗尽和差异认领。对账订单扫描分批执行，保留全历史检查。配置语句/锁/空闲事务超时。

提供非 root Python 镜像、Next standalone 镜像与 Compose 服务启动依赖；运行账户和迁移所有者分离。发布流程见 [运行手册](../operations/runbook.md)。容器定义已校验，镜像构建和生产发布没有在本轮执行。

UI 沿用已选择的“专业资金工作台”：PC 资金、团队、审计与资金操作保持清晰层级；代理端保留 Wise 深色资产卡与列表流。主题来源统一为 `design/tokens.json`，Python 生成 Web CSS 与两套原生 WXSS；移除依赖 DOM 顺序的样式定位。错误、警告、成功和未知结果区分展示。PC 工作区、周期、分页与筛选写入 URL。
