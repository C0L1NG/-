# 功能与 UI 专项检查

日期：2026-10-03。范围：当前工作区的代理商 Web、老板 PC 和老板移动 Web。

## 检查依据与边界

- 浏览器实际检查本地静态展示版：代理商首页、进展、个人中心；老板 PC 总控与代理透视；老板移动大盘与提现入口。
- 检查实际 CSS 视口宽度 375px、430px 和桌面布局；浏览器存在缩放，使用 DOM 返回的视口尺寸核实手机宽度。
- 对照 `web` 正式组件、相关 Python 路由和统计查询。展示版同步检查通过：29 个共享文件一致。
- 本次没有修改业务代码，没有重新验证真实支付、生产登录、数据库并发或微信真机能力。静态演示的提现提示只证明入口可用，不代表付款链路可用。
- 以下区分浏览器复现、代码发现和产品建议；不将演示数据错误推断为正式财务计算错误。

## 总体判断

深色配色、圆角、主次按钮和移动导航已经形成一致风格，适合保留。下一轮应优先提高信息可信度、操作完成度与可读性。继续增加装饰和光效的收益较小。

## 优先修复的问题

### 1. 老板演示页团队金额出现 NaN

- 证据：PC 全周期页面中，一级团队的 GMV 和平台贡献实际显示 `¥NaN`。
- 原因：`web/components/admin-network.tsx:18` 直接用 `Number()` 计算带千位逗号的字符串；`web/lib/admin-demo-data.ts:81` 等数据包含 `2,486,320.00`。
- 影响：演示的核心财务信息不可读，直接削弱可信度。正式接口返回数字字符串的路径不据此判定受影响。
- 建议：演示数据保持与 API 相同的未格式化金额契约；金额展示统一格式化，计算使用分或 Decimal；非法值显示明确的不可用状态。增加一条团队汇总展示回归检查。

### 2. 二级代理“获客推广”的说明与实际行为冲突

- 浏览器复现：个人中心提示“分享推广链接获客”，点击“复制链接”却提示“二级伙伴不能继续招募代理”。
- 位置：`web/components/agent-profile.tsx:32`、`:43`、`:61` 与 `:148`。复制、分享、生成海报三个入口均按 49% 身份拦截。
- 后端太阳码也明确用于招募，拒绝二级代理继续发展下一层：`python_backend/app/routers/agent.py:206`。
- 建议：明确区分“客户购买推广”和“代理招募”。客户推广需要独立落地页及出单归属；招募入口按层级展示资格与原因。不能直接删除限制，否则会破坏严格二级规则。如果客户获客链路尚未实现，应准确标注当前功能能力。

### 3. 金额隐藏没有覆盖完整页面

- 浏览器复现：在首页隐藏金额，再进入进展，月度收益变成圆点，但四位团队成员的贡献金额仍完整显示。
- 位置：`web/components/agent-progress.tsx:260` 没有读取 `hidden`；`web/components/agent-ui.tsx:192` 的流水详情也不接收隐藏状态。
- 建议：统一敏感金额组件，覆盖余额、团队贡献、列表和详情；如点击详情需要临时显示金额，应提供明确的显隐操作。

### 4. 浅色主题的高亮文字难以辨认

- 浏览器复现：切换浅色后，底栏选中项和部分图标仍是浅荧光绿，视觉对比不足。
- 位置：`web/components/agent-context.tsx:187` 固定选中色；`web/components/agent-profile.tsx:157` 邀请码固定同一颜色。
- 建议：背景用荧光绿时保留深色文字；文字高亮统一使用已有 `--agent-accent-text`，按主题切换。逐项检查选中态、金额、邀请码、焦点和禁用态。

### 5. 正式导出失败缺少可恢复反馈

- 代码发现：老板移动端直接 `window.location.assign()` 请求导出，外围 `try/catch` 无法处理后续 HTTP 401、403、500；按钮等待态也立即结束。PC 使用直接导航链接。
- 位置：`web/components/admin-mobile-home.tsx:30`、`web/components/admin-dashboard.tsx:268`。
- 影响：会话失效或服务异常时可能离开当前页面，显示接口错误，且不能原地重试。
- 建议：检查响应状态后下载文件，保留页面与筛选状态；大文件用导出任务及下载链接；区分登录过期、无权限、失败和成功。这里是代码路径发现，本次未向真实服务注入故障。

### 6. “实时流水”的刷新范围与文案不一致

- 代码发现：老板移动大盘每 60 秒刷新概览；审计页的 effect 只依赖 `demo/page/revision`，成功态没有用户刷新入口，父级概览更新不会重新请求审计流水。
- 位置：`web/components/admin-mobile-context.tsx:63`、`web/components/admin-mobile-audit.tsx:64`、`:81`。
- 建议：在审计页提供手动刷新、页面重新可见时刷新和最后更新时间；如保留“实时”文案，应明确自动更新间隔。分页时避免旧数据与新数据混入造成重复或漏项。

## 需要补齐的功能体验

### 完整团队入口

代理 Web 进展仅显示前四名（`web/components/agent-progress.tsx:79`，后端 `python_backend/app/queries/agent_metrics.py:108`），没有查看全部成员的入口。建议增加“查看全部 N 人”、搜索、分页与成员贡献详情；明确排行榜是累计贡献，避免与上方本月汇总混淆。已有 `/api/agent/team` 可以复用，仍需严格按当前用户过滤。

### 时间与账目检索

代理明细只有来源筛选与“加载更早记录”，缺少按月或日期快速定位；接口 `/api/agent/activity` 已支持 `from/to`。建议增加本月、上月、自定义日期及区间净收益，清楚标识退款扣回。老板移动审计建议补订单号搜索与日期筛选。

### 老板待办入口

PC 的提现审核、支付恢复位于整页底部（`web/components/admin-dashboard.tsx:320`）。建议顶部增加待审核、处理中、恢复失败的数量与跳转，按紧急程度组织；老板移动端增加资金待办入口，保留现有三 Tab 即可，无需再堆一套导航。

### 钱包与提现信息层级

老板大盘突出累计净收益，旁边就是提现按钮，建议另列可提现、冻结和处理中金额，避免累计收益被理解为可立即提现金额。代理个人中心增加独立提现记录入口，并在收款方式上展示真实绑定状态，减少用户进入弹层后才知道不能操作的情况。

## 视觉细节建议

- 将交易说明、表单提示等重要正文提升到 13–14px；10px 适合装饰性眉题，不适合承载关键财务状态。
- 中文标题可放松过紧字距；英文眉题降低重复出现频率，让余额、状态与下一步操作优先被看到。
- 保留深色大卡和荧光绿 CTA；成功、退款、失败、冻结需要文字与图标共同区分，不能所有条目都呈现相同的绿色成功感。
- 375px 首页实际可用，但资产卡之前的展示文案占据较多高度。可以适度收紧顶部营销文案，使最近一笔入账更早露出；保留卡片内部呼吸感。
- 统一桌面和移动表单的间距、输入错误、按钮等待态与关闭行为。当前通用弹层有焦点管理和 Escape 关闭，适合继续复用。

## 演示数据还需要自洽

`web/lib/demo-data.ts:15` 显示二级代理、49% 自身分润，同时展示 18 名直属下线和 21% 团队奖励；这与当前严格二级、二级不可继续招募的限制矛盾。

建议分别准备一级、二级演示账户：一级展示 70% 自身出单与 21% 团队奖励；二级展示 49% 自身出单且没有直属招募团队。演示日期、筛选范围和汇总值也应相互一致。

## 推荐落地顺序

1. 修 NaN、演示身份矛盾、金额隐藏遗漏、浅色对比问题。
2. 明确客户推广与代理招募的边界，补完整团队入口。
3. 增加日期检索、更新时间、可靠导出和老板待办。
4. 最后统一字号、间距、状态视觉与细微动效。

验收以具体用户路径为单位：两种代理身份推广、隐藏金额后跨页查看、完整团队分页、筛选与导出一致、导出失败原地恢复、审计新数据可见，以及 375px/430px 手机页面阅读。
