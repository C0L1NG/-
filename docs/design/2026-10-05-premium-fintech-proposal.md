# 第四轮视觉与交互优化提案

日期：2026-10-05。范围：老板 PC、老板移动端、代理 Web / 微信小程序。本文是设计方案与验收目标，不代表这些改造已经上线。

## 当前判断

当前页面完成了黑白化，但尚未形成稳定的金融产品设计系统。资金总览、固定分润规则、刷新说明和真实财务任务占据近似的视觉权重；大量组件各自定义灰色、圆角和小字号。结果是页面整齐，却缺乏明确的阅读节奏与工作重点。

实测老板 PC 在 1440 × 900 视口，资金待办从约 713px 处开始，审计区域从约 895px 处开始。首屏更像介绍页，管理员最常处理的异常和资金记录被压到下方。`web/app/globals.css` 只声明 Geist / Inter，没有加载字体；不同系统实际使用的字体不一致。原生小程序与 Web 的金额隐藏、状态文案和分页行为也需要同一套验收标准。

金融产品的高级感应来自：金额可信、层级稳定、对齐准确、操作连续、异常可解释。第四轮应先建立这些标准，再统一材质与动效。

## 方案 A：石墨铂金资金工作台（推荐老板端）

### 配色和表面

- 应用底色：`#0B0C0E`；一级内容面：`#121417`；二级交互面：`#1A1D21`。浮层为 `#20242A`。
- 主文字：`#F3F5F7`；正文：`#C1C7CF`；辅助文字：`#939CA8`；禁用文字：`#626B77`。禁用色不用于正常可读内容。
- 常规分隔：`#252A31`；重要边界 / 选中项：`#3C4652`。尽量用间距与表面对比形成层级，分隔线只用于列、流水、输入框。
- 主操作：少量浅绿 `#C5F5A1` + 深色文字，与聊天中的推荐提案对应；铂金白 `#F3F5F7` 可用于需要保持中性强调的页面。正收益 / 成功：`#35C99A`；退款 / 失败：`#F07887`；待处理 / 风险：`#E6B86A`。绿色不用于错误提示、所有图标或所有排名。
- 一个视图区只保留一个强主操作。将“提交申请”“确认付款”等动作与“复制”“筛选”“导出”等工具区分。

### 字体和数字

- 实际加载一款可自托管的无衬线字体，例如 Geist / Inter；中文明确使用 PingFang SC / Noto Sans CJK SC 系列回退。开发时记录授权与资源大小。
- 资产大金额使用无衬线字体 + `font-variant-numeric: tabular-nums`，不要用大面积等宽字营造科技感。PC 44–52px、手机 36–42px，字重 550–650；小数位可稍弱，禁止隐藏小数或改变原始金额。
- 订单号、时间、百分比、审计金额列使用真正加载的等宽字体；表格金额右对齐，单位与小数口径统一。最大支持金额不能省略号截断。
- PC 页面标题 26–28px / 600；模块标题 16–18px / 600；正文 14px / 400–500；次级说明 12–13px。移动端正文以 14–16px 为主，财务状态不得缩到 10px。

### 间距、圆角、材质

- 使用 4 / 8 / 12 / 16 / 24 / 32 / 48px 间距尺度。桌面主内容外边距 32px；手机 20px，窄屏可到 16px。
- 输入框和按钮圆角 8px、内容容器 12px、移动资产卡 18–20px；避免每个元素都胶囊化。胶囊保留给状态和短筛选。
- 主内容不叠加大阴影。仅浮层与菜单使用低透明度阴影；不加入装饰光斑、霓虹、假玻璃。
- 悬浮 120–160ms，抽屉 180–220ms；只改变透明度、背景或少量位移。遵循减少动态效果设置。

### 老板 PC 布局（1280px 以上）

固定侧导航 208–224px，主内容区最低约 992px。在 1280 / 1440 / 1920px 三档验收，不让内容在大屏上无限拉长；主要财务工作区最大宽度约 1520px。

1. 顶部工具栏 56px：当前位置、业务周期、数据最后成功更新时间、搜索、账户。取消重复的面包屑 + 大英文标签 + 大标题组合。
2. 资金摘要区域约 200px：主位展示平台可提现余额；旁边显示冻结、待付款、累计净收益。GMV 与代理佣金作为经营指标放在第二层，避免把累计净收益当成当前可支配资金。
3. 同屏双列工作区：左侧约 65% 显示最近资金活动或异常订单；右侧约 35% 显示待审核、处理中、失败待恢复与待核验。待办按状态与时效排序，点击直接进入对应筛选。
4. 总览首屏至少可见 4–6 条真实审计记录或可执行待办。30 / 49 / 21 分配规则下沉为信息提示或详情说明，不占据首屏大卡片。
5. “代理网络”使用紧凑分层列表，每行含可比指标；右侧详情抽屉 400–460px。展开二级只增加必要行，保留列对齐、周期与搜索上下文。
6. “分账审计”采用可扫描的结构化表格，弱线条而非取消表格语义。固定金额列对齐；点击订单打开侧抽屉，展示原始入账、冲正、付款记录时间线。
7. “资金管理”独立路由，可保存状态、页码和选中订单到 URL；刷新、后退、转发链接后能回到同一工作位置。

## 方案 B：留白财富账户（推荐代理端）

代理只需要知道可提现多少、最近赚到多少、如何完成提现和邀请。首页应采用更舒展的账户界面；深色骨架与老板端共用，但密度、说明和操作数量更克制。

### 375–430px 手机布局

1. 顶部身份栏 48px：头像、昵称、当前代理层级；不同时展示多个装饰英文标签。
2. 资产区 180–220px：可提现余额为唯一核心数字，显隐按钮在旁；冻结 / 待结算通过可展开说明显示。主操作“申请提现”；分享邀请为次操作或独立入口。
3. 今日 / 本月收益以两列小指标展示。所有统计标明时间口径；负收益显示负号与退款语义，不继续使用绿色正向展示。
4. 最新 2 条资金活动为连续列表，不为每条套独立大卡片，并提供全部明细入口。左侧来源图标、中间来源与时间、右侧金额；长订单号在详情中完整展示。
5. 导航保留首页 / 进展 / 明细 / 我的；第二层页面有清晰返回路径，所有触摸目标至少 44 × 44px。
6. 详情使用底部抽屉；金额与订单号完整显示。桌面管理端则改用右侧抽屉，避免在 1440px 屏幕中出现仅 430px 宽的手机底部弹层。
7. 一级与二级使用真实资格文案；二级“不能继续发展代理”的提示只出现于邀请入口，不占据资产页核心空间。

浅色可作为同一套 token 的替换模式：暖灰底 `#F4F5F3`、白色资产区、深石墨数字。它应与暗色共享状态和尺寸，不另写一套布局。

## 数据、状态与交互验收

- 首次加载显示与最终内容同宽同高的骨架；后台刷新保留已知数据并提示更新中。局部接口失败只影响局部模块，不能把有效登录用户整页换成登录入口。
- 刷新按当前模块触发，显示该模块最后成功时间。提现、支付恢复、待核验列表必须响应页面刷新；不可只刷新顶部摘要而继续展示旧操作列表。
- 自动刷新不能把用户从第 3 页拉回第 1 页，也不能关闭正在查看的分账详情。可以显示“有新记录”，由用户决定更新顶部列表；涉及当前选中状态变化时明确提示并重新核对。
- 原生分页请求使用序号保护或取消机制；请求页与响应页绑定。连点下一页、慢网、切页再返回时，旧响应不得替换当前页或新余额。
- 筛选区显示已应用条件与结果数量。自定义日期编辑态与已应用态明确区分；清空后恢复全部。失败不应把总数 / 净入账静默显示成 0。
- 金额支持 0、负数、退款冲正、数据库支持的最大值；不得使用 JavaScript 浮点数计算入账。大金额需要自然换行或合理收缩，禁止遮挡其他关键字段。
- 财务动作区分待提交、提交中、成功、失败、结果未知；重复点击不会重复申请。失败文案使用红色 / 琥珀色语义与可执行恢复入口。
- 弹层支持焦点进入、Tab 约束、Escape、关闭后回焦；危险操作处理中不允许产生不明确结果。移动端考虑键盘遮挡与安全区。
- 正文对比度目标至少 4.5:1，状态不能只靠颜色；移动端文本最小 12px，金额与业务操作优先 14px 以上。
- Web 与小程序共用词汇：待审核 / 处理中 / 已付款 / 已驳回，不直接展示 `processing` 等接口枚举。收款选择器必须显示当前选中账户的脱敏名称。

## 实施顺序

1. 先修确定的交互问题：资金刷新不生效、原生提现分页竞态、自动刷新打断阅读、全局错误遮挡局部功能。
2. 提取统一 token 与组件：金额、状态、按钮、字段、加载 / 错误 / 空状态、列表、PC 抽屉、移动抽屉。先覆盖资金相关页面。
3. 先交付老板 PC 总览 + 审计、代理首页 + 明细四个代表页面；在真实边界数据下验收，再扩展其余页面和原生小程序。
4. 增加页面行为回归：刷新命中当前模块、分页稳定、后退保留上下文、键盘可达、375px 无金额裁切。避免只验证演示快照和截图外观。
